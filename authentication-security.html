Chapter 6

Authentication & Security

Security is not a feature added at the end — it's a property of the entire system. Master JWT, OAuth2, RBAC, and the OWASP Top 10 to build systems that protect user data and resist attacks.

⏱ 75 min read 🎯 All Levels 🔐 OWASP + Auth flows

Authentication vs Authorization

Authentication (AuthN) — "Who are you?" Verifying identity. Authorization (AuthZ) — "What can you do?" Checking permissions. They are separate concerns and should be handled separately.

ConceptQuestionExampleImplementation
AuthenticationWho are you?Validating username + password / JWT / API keyMiddleware that verifies credentials before handler runs
AuthorizationWhat can you do?User can read but not delete; admin can do everythingRBAC/ABAC policy check after authentication
IdentificationWho do you claim to be?The userId in the JWT payloadExtracted from validated token

JWT — JSON Web Tokens

JWTs are self-contained tokens. The server encodes claims and signs them. The client stores the token and sends it with every request. No DB lookup needed to verify — just re-verify the signature.

# JWT structure: header.payload.signature (each base64url-encoded)
# Header: {"alg": "RS256", "typ": "JWT"}
# Payload: {"sub": "1001", "email": "alice@co.com", "role": "admin", "exp": 1735689600, "iat": 1735603200}
# Signature: RSASHA256(base64(header) + "." + base64(payload), privateKey)

# Python: creating and verifying JWTs with PyJWT
import jwt, datetime
from cryptography.hazmat.primitives import serialization

# Load RSA keys (use RS256 — NOT HS256 in production)
with open("private.pem", "rb") as f:
    PRIVATE_KEY = serialization.load_pem_private_key(f.read(), password=None)
with open("public.pem", "rb") as f:
    PUBLIC_KEY = serialization.load_pem_public_key(f.read())

def create_access_token(user_id: int, role: str) -> str:
    payload = {
        "sub": str(user_id),
        "role": role,
        "iat": datetime.datetime.utcnow(),
        "exp": datetime.datetime.utcnow() + datetime.timedelta(minutes=15),
        "jti": str(uuid.uuid4()),  # unique token ID for revocation
    }
    return jwt.encode(payload, PRIVATE_KEY, algorithm="RS256")

def verify_token(token: str) -> dict:
    try:
        payload = jwt.decode(token, PUBLIC_KEY, algorithms=["RS256"])
        return payload
    except jwt.ExpiredSignatureError:
        raise HTTPException(401, "Token expired")
    except jwt.InvalidTokenError:
        raise HTTPException(401, "Invalid token")
🚨 JWT Security Anti-patterns: Never use alg: none. Never use HS256 with a weak secret. Never store sensitive data (passwords, PII) in the payload — it's only base64-encoded, not encrypted. Always validate exp, iss, and aud claims. Short expiry (15 min) + refresh tokens > long-lived access tokens.

OAuth2 & OpenID Connect

OAuth2 is an authorization framework. OpenID Connect (OIDC) adds an authentication layer on top. Together they power "Login with Google/GitHub/Apple".

1
User clicks "Login with Google" → Your app redirects to Google's auth endpoint with client_id, redirect_uri, scope=openid email, and a random state parameter
2
User approves → Google redirects back to your redirect_uri with an authorization code and the state you sent (verify it!)
3
Server exchanges code → Your backend calls Google's token endpoint with the code + client_secret. Returns access_token, refresh_token, and id_token
4
Get user info → Decode the id_token (OIDC JWT) or call /userinfo endpoint to get user's email, name, and profile
5
Create session → Look up or create user in your DB. Issue your own JWT/session token. The Google tokens are now disposable

RBAC & ABAC

// RBAC: Role-Based Access Control (most common)
// Roles: admin, editor, viewer. Permissions assigned to roles.

const PERMISSIONS = {
  admin:  ['read', 'write', 'delete', 'manage_users'],
  editor: ['read', 'write'],
  viewer: ['read'],
};

function requirePermission(permission: string) {
  return (req, res, next) => {
    const { role } = req.user;
    if (!PERMISSIONS[role]?.includes(permission)) {
      return res.status(403).json({ error: 'Forbidden' });
    }
    next();
  };
}

// Usage:
router.delete('/posts/:id', requirePermission('delete'), deletePost);

// ABAC: Attribute-Based — more granular, checks context
// "User can edit post ONLY IF they are the author AND post.status !== 'published'"
function canEditPost(user, post): boolean {
  return user.id === post.authorId
    && post.status !== 'published'
    && !user.isBanned;
}

# Password hashing — ALWAYS use bcrypt or argon2, NEVER md5/sha1
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["argon2"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)
    # → "$argon2id$v=19$m=65536,t=3,p=4$..."

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)
    # Constant-time comparison — no timing attacks

# SQL Injection prevention — parameterized queries
# ❌ VULNERABLE:
query = f"SELECT * FROM users WHERE email = '{email}'"

# ✅ SAFE (parameterized):
user = await conn.fetchrow(
    "SELECT * FROM users WHERE email = $1", email
)  # Driver handles escaping; injection is impossible

Secrets Management

🚨 Never hardcode secrets. Don't put DB passwords, API keys, or JWT secrets in code, config files, or environment variables in Docker images. Use a secrets manager.
Secrets Managers
  • AWS Secrets Manager: auto-rotation, IAM integration, RDS secrets
  • HashiCorp Vault: open-source, dynamic secrets, audit logging
  • GCP Secret Manager: versioned, IAM-controlled
  • Azure Key Vault: HSM-backed, certificate management
  • Doppler / Infisical: developer-friendly secret sync across environments
Defense in Depth
  • TLS everywhere (HTTPS, mTLS between services)
  • Rotate credentials regularly (90-day max for API keys)
  • Principle of least privilege — services get only the permissions they need
  • Audit logs for all secret access
  • Network segmentation — DB not accessible from public internet
  • WAF (Web Application Firewall) in front of APIs
