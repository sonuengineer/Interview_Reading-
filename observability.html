Chapter 10

Observability & Monitoring

You can't fix what you can't see. Observability is the ability to understand your system's internal state from its external outputs. Master the three pillars — metrics, logs, traces — and instrument your systems like a senior SRE.

⏱ 60 min read 🎯 All Levels 📊 Prometheus, OTel, Jaeger

The Three Pillars

📊 Metrics

Tell you WHAT happened — aggregated numerical data over time. High-level system health.

  • Request rate, error rate, latency (RED pattern)
  • CPU, memory, disk, network (USE pattern)
  • Business KPIs: orders/min, revenue/sec
  • Tools: Prometheus, Datadog, CloudWatch
  • Visualization: Grafana, Kibana
📋 Logs

Tell you WHERE it happened — detailed event records. Debug individual failures.

  • Structured JSON logs (queryable, filterable)
  • Include: timestamp, level, service, trace_id, user_id
  • Tools: ELK Stack (Elasticsearch + Logstash + Kibana)
  • Alternatives: Loki + Grafana, Datadog Logs, Splunk
  • Log sampling at high volume to reduce costs
🔍 Traces

Tell you HOW it happened — follow a request across all services. Find the exact span that caused a slowdown.

  • Distributed tracing: trace_id propagated across services
  • Waterfall view shows each service's contribution to latency
  • Tools: Jaeger, Zipkin, Datadog APM, Honeycomb
  • Standard: OpenTelemetry (vendor-neutral)

Prometheus & Grafana

Prometheus scrapes metrics from your services on a schedule. Grafana visualizes them. Together they're the standard for production monitoring.

# FastAPI + Prometheus instrumentation
from fastapi import FastAPI, Request
from prometheus_client import Counter, Histogram, generate_latest, CONTENT_TYPE_LATEST
import time

app = FastAPI()

# Define metrics
REQUEST_COUNT = Counter(
    'http_requests_total',
    'Total HTTP requests',
    ['method', 'endpoint', 'status_code']
)
REQUEST_LATENCY = Histogram(
    'http_request_duration_seconds',
    'HTTP request latency',
    ['method', 'endpoint'],
    buckets=[.005, .01, .025, .05, .1, .25, .5, 1, 2.5, 5]
)

@app.middleware("http")
async def metrics_middleware(request: Request, call_next):
    start = time.time()
    response = await call_next(request)
    duration = time.time() - start

    REQUEST_COUNT.labels(
        method=request.method,
        endpoint=request.url.path,
        status_code=response.status_code
    ).inc()
    REQUEST_LATENCY.labels(
        method=request.method,
        endpoint=request.url.path
    ).observe(duration)
    return response

# Expose /metrics endpoint for Prometheus to scrape
@app.get("/metrics")
async def metrics():
    from fastapi.responses import Response
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)
# Prometheus config (prometheus.yml)
global:
  scrape_interval: 15s
  evaluation_interval: 15s

alerting:
  alertmanagers:
    - static_configs:
        - targets: ['alertmanager:9093']

rule_files:
  - "alerts/*.yml"

scrape_configs:
  - job_name: 'api-service'
    static_configs:
      - targets: ['api:8080']
    metrics_path: /metrics

---
# Key PromQL queries:
# Request rate:  rate(http_requests_total[5m])
# Error rate:    rate(http_requests_total{status_code=~"5.."}[5m]) / rate(http_requests_total[5m])
# P99 latency:   histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m]))

OpenTelemetry

OpenTelemetry (OTel) is the CNCF standard for vendor-neutral instrumentation. Instrument once, export to any backend (Jaeger, Datadog, Honeycomb, Grafana Tempo).

# OpenTelemetry: distributed tracing in Python
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.jaeger.thrift import JaegerExporter
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor

# Setup
jaeger_exporter = JaegerExporter(agent_host_name="jaeger", agent_port=6831)
provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(jaeger_exporter))
trace.set_tracer_provider(provider)

# Auto-instrument FastAPI (all requests automatically traced)
FastAPIInstrumentor.instrument_app(app)

# Manual spans for custom operations
tracer = trace.get_tracer(__name__)

async def process_order(order_id: str):
    with tracer.start_as_current_span("process_order") as span:
        span.set_attribute("order.id", order_id)
        span.set_attribute("service.name", "order-service")

        with tracer.start_as_current_span("validate_payment"):
            result = await validate_payment(order_id)

        with tracer.start_as_current_span("update_inventory"):
            await update_inventory(order_id)

Structured Logging Best Practices

// Structured logging with Winston (Node.js)
import winston from 'winston';

const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.errors({ stack: true }),
    winston.format.json()  // structured JSON — queryable in ELK
  ),
  transports: [new winston.transports.Console()],
});

// Log with context — always include trace_id and user_id
function getLogger(ctx: RequestContext) {
  return logger.child({
    traceId: ctx.traceId,
    userId: ctx.userId,
    service: 'order-service',
    version: process.env.APP_VERSION,
  });
}

// Usage:
const log = getLogger(ctx);
log.info('Order created', { orderId, amount, currency });
log.error('Payment failed', { orderId, error: err.message, stack: err.stack });

// Output (one JSON line per event — ELK can index and query any field):
// {"level":"info","message":"Order created","orderId":"ord_123","amount":5999,
//  "traceId":"abc-def","userId":"usr_456","timestamp":"2025-01-15T10:30:00Z"}

SLIs, SLOs, and SLAs

TermDefinitionExample
SLI (Service Level Indicator)A specific metric that measures service behaviorP99 latency, availability %, error rate
SLO (Service Level Objective)Target value for an SLI. Internal engineering goal"P99 latency < 200ms measured over 30 days"
SLA (Service Level Agreement)Contract with customers. Violation = penalty"99.9% availability per month or 10% credit"
Error BudgetHow much you're allowed to fail while meeting SLO99.9% SLO = 43.8 min/month downtime budget
